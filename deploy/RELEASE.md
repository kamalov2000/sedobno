# Релиз-день: калории + подписки v2 + гейт галлюцинаций

Один выкат вместо трёх: ветка `feature/calories` несёт модуль калорий, антигаллюцинационный
гейт сканера и подписки v2 (автопродление + годовой тариф). Мержится в `main` целиком —
значит и откатывать придётся целиком, поэтому порядок ниже не «на всякий случай», а
обязательная часть выката.

Что делает выкат необратимым без подготовки: **миграции 0009–0015**. Код откатывается
`git checkout` за минуту, схема — нет. Отсюда правило: бэкап снимается ДО миграций, и его
восстановление проверяется на бете, а не в момент аварии.

---

## 0. За сутки до

- [ ] Вебхук в БОЕВОМ кабинете ЮKassa: `https://<домен>/api/payments/sbp/webhook`,
      событие `payment.succeeded`. Без него автопродления не подтвердятся — деньги
      спишутся, доступ не продлится.
- [ ] Рекуррентные платежи включены в боевом магазине ЮKassa (письмо менеджеру, зависит
      от их скорости — единственный внешний блокер).
- [ ] Оферта/лендинг с формулировками про автопродление опубликованы. Порядок важен:
      рекуррентный инвойс нельзя включать раньше документов, иначе документы обещают
      разовый платёж, а списывается подписка.
- [ ] На проде проверить `SBP_ANNUAL_PRICE_RUB` (2490) и `SBP_PRICE_RUB` (249).

## 1. Бэкап ДО миграций (обязательно)

```bash
cd /opt/sostav
mkdir -p /opt/backups
STAMP=$(date +%Y%m%d-%H%M%S)
docker compose -f deploy/docker-compose.yml --env-file .env exec -T postgres \
  pg_dump -U "$(grep -E '^POSTGRES_USER=' .env | cut -d= -f2)" \
          -d "$(grep -E '^POSTGRES_DB=' .env | cut -d= -f2)" -Fc \
  > /opt/backups/sostav-$STAMP.dump
ls -lh /opt/backups/sostav-$STAMP.dump      # размер НЕ должен быть нулевым
```

- [ ] Дамп снят, размер осмысленный.
- [ ] Записать номер версии схемы ДО выката: `SELECT max(version_id) FROM goose_db_version;`
      (ожидаем 8 на проде, 15 после выката).
- [ ] Проверить, что дамп читается: `pg_restore --list /opt/backups/sostav-$STAMP.dump | head`.

## 2. Выкат

**Сначала — обязательная правка `.env`, до `make deploy`.**

```bash
cd /opt/sostav
grep -q '^LLM_TIMEOUT_SEC=' .env \
  && sed -i 's|^LLM_TIMEOUT_SEC=.*|LLM_TIMEOUT_SEC=40|' .env \
  || echo 'LLM_TIMEOUT_SEC=40' >> .env
echo 'EXPLAIN_ENABLED=true' >> .env    # если строки ещё нет: фаза 4, дефолт в коде — off
```

- [ ] `LLM_TIMEOUT_SEC=40` в прод-`.env`.

  **Почему обязательно, а не «по метрике».** Таймаут действует НА ПОПЫТКУ, и таймаут
  считается транзиентным — то есть ретраится (`maxLLMAttempts=2`, бэкофф 300 мс).
  Медленный вызов при 25 с стоит не «нет ответа», а **≈50 с и две оплаченные попытки**.
  Прицельная перепроверка плотных этикеток ждёт ОБА вызова, поэтому подвисший
  контрольный держит пользователя, хотя основной ответ уже готов. Замер на бете: вызов
  Sonnet на плотном кадре 18–22 с при пороге 25 с — запас 3–7 с, слишком тонкий. При
  40 с медленный хвост укладывается в одну попытку. Основание механическое, телеметрии
  не требует (на бете её и не набралось — трафика нет).

- [ ] `EXPLAIN_ENABLED=true` в прод-`.env` (иначе «тейк модели» на карточке результата
  не появится: дефолт в коде — выключено).
- [ ] `goose_db_version` = 15.
- [ ] Скан работает (одно фото → балл).
- [ ] Разбор еды работает (одно фото → блюда).
- [ ] Пейволл открывается, оба тарифа видны.

## 3. Откат

Четыре уровня — от дешёвого к дорогому. Выбирается по тому, ЧТО сломалось.

### 3.1. Сломался код, схема цела (самый частый случай)

Миграции 0009–0015 **аддитивные**: новые таблицы (`meals`, `weights`, `water`,
`nutrition_profile`) и новые колонки подписок. Старый код их просто не видит — он
работает на прежней схеме без изменений. Значит откат кода безопасен и мгновенен:

```bash
cd /opt/sostav
git checkout <коммит-до-релиза>
make deploy
```

Данные калорий и подписок v2 остаются в БД и подхватятся при повторном выкате.

- [ ] `curl /api/health` зелёный, скан работает.

### 3.2. Сломались подписки (списания/активации), остальное живо

Не откатывать весь релиз: выключить платный канал и разобраться.

```bash
sed -i 's|^SBP_ENABLED=true|SBP_ENABLED=false|' .env
make deploy
```

Ручки `/payments/sbp/*` отдают 404, планировщик автосписаний не запускается
(`chargeDueSubscriptions` выходит на `!SBPEnabled`), уже выданные подписки продолжают
действовать до конца оплаченного периода. Stars при этом работает.

### 3.3. Скан дороже или медленнее, чем закладывали

Стоимость сканера регулируется двумя переменными, обе — без пересборки и без отката
кода. Порядок именно такой: сначала отключается перепроверка (дороже всего на кадр,
но касается ~12% сканов), и только потом — сама форс-эскалация (дешевле, но вернёт
сочинённые составы на плотных этикетках, ради которых её и вводили).

Обе переменные в `.env` по умолчанию ОТСУТСТВУЮТ (работают дефолты из кода), поэтому
`sed` по существующей строке молча ничего не сделает — дописываем:

```bash
cd /opt/sostav
echo 'SCAN_SELF_CONSISTENCY=false' >> .env       # второе прочтение выкл
# крайняя мера — вернуть дешёвую модель на плотные кадры (сочинённые составы вернутся):
# echo 'SCAN_FORCE_ESCALATE_FINE_LOSS=0' >> .env
make deploy
docker compose -f deploy/docker-compose.yml --env-file .env exec api env | grep SCAN_  # проверить, что доехало
```

Замеры на бете (кадр онигири, `fine_loss` 0.69): одиночная эскалация 4.25 ₽ и 24.9 с,
пара с перепроверкой 8.4 ₽ и 22–25 с. То есть выключение чинит **цену**, а не
латентность: вызовы параллельны, и на времени ответа перепроверка не сказывается.
Если жалоба про «скан думает долго» — переменная не поможет, дело не в ней.

- [ ] `/api/me` → `sbp_available: false`.
- [ ] В логах нет строк «автосписание:».

### 3.4. Побилась схема или данные (последний уровень)

```bash
cd /opt/sostav
make down
docker compose -f deploy/docker-compose.yml --env-file .env up -d postgres
docker compose -f deploy/docker-compose.yml --env-file .env exec -T postgres \
  psql -U <user> -c 'DROP DATABASE <db>; CREATE DATABASE <db>;'
docker compose -f deploy/docker-compose.yml --env-file .env exec -T postgres \
  pg_restore -U <user> -d <db> < /opt/backups/sostav-<STAMP>.dump
git checkout <коммит-до-релиза>
make deploy
```

Цена такого отката — потеря всего, что произошло ПОСЛЕ снятия дампа (сканы, приёмы,
платежи). Поэтому: снимать дамп непосредственно перед выкатом и не тянуть с решением.

**Оплаты, прошедшие после дампа, восстанавливаются вручную:** список платежей есть в
кабинете ЮKassa (и в Telegram — для Stars). Активировать подписку по `telegram_id`
можно SQL из `deploy/BETA.md` (раздел «Выдать тестеру подписку вручную»), заменив
беты-параметры на прод.

### Чего откат НЕ умеет

- Вернуть деньги — это только из кабинета ЮKassa.
- Отменить уже отправленные пользователям уведомления о продлении.
- `goose down` на 0015 удалит колонки подписок v2 вместе с сохранёнными способами оплаты —
  после этого автопродление у всех подписчиков молча превратится в разовую подписку.
  **Не использовать** как способ отката: достаточно 3.1 (старый код игнорирует новые колонки).
