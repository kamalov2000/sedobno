# Падение dockerd на общем VPS — 09.10.2026

**Итог:** сборка образов беты на общем сервере уронила сам Docker; после его перезапуска
контейнеры прода «Съедобно» и astra-dev остались остановленными. Прод недоступен ~6 минут,
astra-dev ~6,5 минуты. Данные не потеряны.

## Причина

1. **Непосредственная — ошибка в buildkit внутри dockerd** (Docker Engine 29.6.0,
   containerd 2.2.5): гонка `subBuilder.EachValue` ← `loadProxyNetwork` ←
   `sharedOp.getOp/CacheMap`, процесс dockerd завершается целиком. Публичного описания этой
   ошибки на 09.10 не нашли.
2. **Условие, при котором она сработала — четыре одновременные сборки.** Compose беты собирал
   один и тот же контекст `../api` трижды (`migrate-beta`, `seed-beta`, `api-beta`) и `web-beta`
   параллельно; падение — ровно в коде, который объединяет одинаковые шаги разных сборок
   (`sharedOp`). В журнале четыре оборванные сессии сборки. За тот же вечер такие сборки
   прошли несколько раз без сбоя — гонка срабатывает не каждый раз.
3. **Почему лёг прод, а не только бета.** Все три стека (прод, бета, astra-dev) делят один
   dockerd. `live-restore` не включён (`/etc/docker/daemon.json` нет), поэтому перезапуск
   dockerd останавливает все контейнеры. `restart: unless-stopped` их обратно **не поднял** —
   наблюдаемый факт; почему именно (особенность восстановления после аварийного завершения в
   29.6.0) — не установлено.
4. **Почему 6 минут.** Мониторинга и оповещения нет: заметили случайно, по своей проверке.
   После упавшего `make beta-up` его просто повторили, не проверив остальные стеки.

## Восстановление (если повторится)

Признак: `curl https://sedobno-pay.ru/api/health` не отвечает, `docker ps -a` показывает
`Exited` у `sostav-*`.

1. Не пересобирать и не перевыкатывать — поднять ТЕ ЖЕ контейнеры:
   ```bash
   docker start sostav-postgres-1 && sleep 5 && docker start sostav-api-1 sostav-web-1 sostav-caddy-1
   ```
2. astra-dev (его одноразовый `astra-dev-astra-migrate-1` не трогать):
   ```bash
   docker start astra-dev-astra-postgres-1 astra-dev-astra-redis-1 && sleep 5 && docker start astra-dev-astra-api-1 astra-dev-astra-worker-1 astra-dev-astra-web-1
   ```
3. Бета: `cd /opt/sostav-beta && make beta-up` (из привезённых образов, без сборки).
4. Проверить всё разом: `cd /opt/sostav && make stacks-health` — три адреса и список
   остановленных контейнеров.
5. Сохранить журналы до ротации: `journalctl --since … --until …` (всё, `-u docker`,
   `-u containerd`) в `/root/incidents/<дата>/`.

## Что изменено

- **Сборок на сервере больше нет** (коммит с этим файлом). Образы собирает и привозит
  `scripts/ship_images.sh beta|prod` с машины разработки: `git archive` коммита →
  статика и образы linux/amd64 локально → `docker save | ssh docker load` (загрузка готового
  образа, не сборка). В compose прода и беты вместо `build:` — образ `:current` и
  `pull_policy: never`: compose на сервере физически не может собирать. `make beta-up` и
  `make deploy` берут образ, помеченный коммитом СВОЕГО HEAD, и отказываются работать без
  него. migrate/seed/api — один образ, а не три сборки. Локальная разработка — через
  `deploy/docker-compose.build.yml` (`make build`, `make up`).
- **`make stacks-health`** после каждого выката: прод, бета, astra-dev и остановленные
  контейнеры. Повторный сбой это не предотвращает — только сокращает время до обнаружения.
- `make beta-deploy` тянет свою ветку (раньше — устаревшую `feature/calories`).

## Не сделано — нужно решение владельца

- **`live-restore: true` в `/etc/docker/daemon.json`** (+ `systemctl reload docker`):
  контейнеры переживают падение и перезапуск dockerd. Защищает от ЛЮБОЙ причины падения
  демона, не только сборок. Это смена системной настройки боевого сервера — только с
  разрешения.
- **Внешний мониторинг с оповещением** (проверка `/api/health` раз в минуту, сообщение в
  Telegram): сейчас о падении узнать неоткуда.
- **astra-dev**: его образы (`astra-backend:dev-…`) созданы на этом сервере ~за час до сбоя —
  собирались ли они здесь, по журналам не установить. Если Астра собирается на сервере, у неё
  тот же риск для всех стеков — вопрос к её сессии.
- Обновление Docker с 29.6.0 — исправления этой гонки в известных выпусках не нашли;
  смысл появится, если найдётся.
